# etd-host-core

Host-side library holding everything the host does that is not an OS call: the
`etd.v1` contract service (gRPC server side), authorisation, the kernel store, the
lifecycle orchestrator with one supervisor per instance, the startup self-check, and
the reclaimers for the host's own records (kernel processes and runtime directories).
It is written only against trait crates; every real implementation (process engine,
SQLite ledger, OS observers and reclaimers, port fence, kernel driver) is injected by
the composition root, [`etd-host`](../etd-host/README.md), through `api::HostDeps`. Its
tests run against fakes and never compile EasyTier.

## How it works

- **Requests (service side).** Every RPC, streaming ones included, passes the same
  guard: version metadata, peer credentials from the IPC layer, role from the
  authorizer. A service host maps peers through the ledger allow list; an admin
  entry counts only for an elevated peer, otherwise it acts as control and admin
  methods answer `ELEVATION_REQUIRED`. A user host grants admin to its owning user
  only. An elevated session host grants control to its owning user in its own Windows
  session and admin only when that peer is elevated (otherwise admin methods answer
  `ELEVATION_REQUIRED`); it has no allow list. Mutations are idempotent by request ID and
  content digest (the network secret enters the digest only as a keyed MAC): a known
  request returns its original receipt without planning again.
- **Plan, commit, execute.** The service asks the orchestrator to plan
  (`Command::Plan`), commits the change and the planned generation in one ledger
  transaction, replies with the receipt and sends `Command::Committed`. The
  orchestrator then executes pending tickets oldest first, always from the committed
  desired state as it is now.
- **Lifecycle.** One supervisor task per instance owns its kernel process. Each start
  is a new generation `(instance, epoch)` whose side effects are planned and recorded
  before any of them happens; every exit goes through reclaim, and a restart is only
  possible after the previous generation is closed. Basic readiness comes from system
  observation (and a verified management-port fence on a service host); full
  readiness means the kernel's management session answered. Details:
  [docs/lifecycle.md](docs/lifecycle.md).
- **Self-check.** Before serving, open process records and orphan kernels are killed
  or quarantined, open generations are reclaimed, and nothing is reclaimed or started
  while a kernel of ours might still be alive. A newer or unreadable ledger schema
  gives diagnose-only mode: nothing is killed, deleted or started.
- **Kernel store.** A kernel is usable only if its manifest entry matches the embedded
  release table and every bundle file hashes correctly at resolve time. A privileged
  host requires an adapter profile for the version; a user host without one runs the
  kernel lifecycle-only (start, stop, logs, no RPC). Clients can name a version, never
  a path.
- **Host lifetime.** A user host (and an elevated session host) stops its
  instances and exits after 30 s with no lease holder, or when a client releases its
  lease with "stop instances". A service host ignores leases.

## Dependencies and boundaries

- **Used by:** `etd-host` (normal), `etd-testkit` (normal; test-only crate).
- **Depends on:** `etd-contract`, `etd-ipc`, `etd-proc`, `etd-sysfx`, `etd-core-api`;
  `etd-testkit` as a dev-dependency.
- **Must not depend on:** any other workspace crate, in particular `etd-sysfx-os`,
  `etd-core-easytier` or any `easytier*` crate, nor on system binding crates
  (boundary 3 in `xtask/src/boundaries.rs`).

## Key modules

| Module | Responsibility |
| --- | --- |
| `api` | Frozen handle between service and orchestrator; `HostDeps`. |
| `service/` | Contract RPCs, request idempotency, allow-list publication, ledger-failure handling (a stop that cannot be committed becomes `Command::Cut`). |
| `auth`, `auth/allow_list` | Role mapping from OS peer identity. |
| `negotiate`, `events` | Version checks; event journal and resumable cursors. |
| `core_store`, `core_store/manifest` | Kernel store trait and manifest-backed implementation. |
| `lifecycle/mod` | Orchestrator actor: self-check, commands, tickets, purge, leases, shutdown. |
| `lifecycle/machine` | Allowed state edges. |
| `lifecycle/plan` | Planning a generation, guard choice, replay of a committed generation. |
| `lifecycle/view` | Publisher of gap-free events and the `HostView`; secret redaction. |
| `lifecycle/logs` | Bounded per-instance and host log books; line-based redaction. |
| `supervisor` | Per-instance state machine: launch, readiness, stop, cut, reclaim, backoff, quarantine. |
| `boot` | Startup self-check and re-sweep. |
| `fence_seq` | Management-port fence install and verification. |
| `poller` | Poll period of the management session. |
| `reclaimers` | Verified-kill process reclaimer and runtime-directory reclaimer. |

## Testing

```sh
cargo nextest run -p etd-host-core
cargo test --doc -p etd-host-core
```

All tests are unprivileged and use the fakes from `etd-testkit` (fake process engine,
ledger, observer, fence, kernel driver, clock):

- `lifecycle_states`, `lifecycle_exits`, `lifecycle_epoch`: give-up, cut, waiting,
  quarantine, every way a kernel ends, no overlapping generations.
- `lifecycle_edges`: every edge of `machine::EDGES` is taken by some scenario
  (exceptions listed with a reason).
- `lifecycle_fence`, `lifecycle_poll`, `lifecycle_reclaimers`: fence sequence, poll
  rate, process recovery convention and runtime-directory reclaim.
- `boot_selfcheck`: self-check order, crash recovery, idempotence, ledger-less modes.
- `core_store`: manifest trust, hashing, removal.
- `service_*`: handshake, roles, idempotent mutations, events, allow-list sink,
  version interceptor (in-process gRPC transport).

[docs/architecture/host.md](../../docs/architecture/host.md).
